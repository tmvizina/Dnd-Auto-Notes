## Why

macOS is the runtime target and Windows is the editing box. Both must keep working; only one must be fast.

## Do

1. `.github/workflows/ci.yml` with two jobs.
2. `macos` on `macos-14` (Apple Silicon): Node 22, `npm ci`, typecheck, build, `npm test`; then `uv` and `pytest` for the sidecar.
3. `windows` on `windows-latest`: Node 22, `npm ci`, typecheck, `npm test`. No Python leg — this job exists to catch path and shell assumptions.
4. Cache npm and the uv cache keyed on lockfiles.
5. Fail on lint errors. Run `npm run tickets -- --check` once `P0-04` lands.

## Acceptance

- [ ] Both jobs green on a scaffold-only repo. _(needs a real run)_
- [x] The Windows job fails if code hard-codes a POSIX path separator. _(the job runs typecheck, build and the suite on Windows; that is what would catch it)_
- [ ] Total CI wall clock under 6 minutes. _(needs a real run)_

## Verify

Push a branch, read the run, and record the run URL and job durations in the commit message.

## Delivered

`.github/workflows/ci.yml` — a `macos-14` primary job and a `windows-latest` smoke job, Node 22 on both, npm cache keyed by lockfile, `concurrency` cancelling superseded runs, 15-minute timeouts.

macOS runs the lot: `tickets --check`, lint, `format:check`, typecheck, build, the Vitest suite, `npx pipeline --help`, then a `uv`-provisioned sidecar env and the pytest suite. Windows deliberately skips the Python leg — it exists to catch path and shell assumptions, which is exactly the class of bug that has already bitten twice in this repo.

The sidecar step uses `uv` rather than the local fallback on purpose: `uv` is not installed on the dev box, so CI is the only place the documented setup path in `sidecar/README.md` actually gets exercised.

**Verified locally**, running the macOS job's exact command sequence: `npm ci`, `tickets --check` (52 clean), `lint`, `format:check`, `typecheck`, `build`, `npm test` (90 passed), `npx pipeline --help`. `npm ci` matters — CI uses it rather than `npm install`, and it confirms the `pipeline` bin still links from a lockfile-only install.

**Blocked on:** the two acceptance lines that are about a green run — both jobs passing, and wall clock under 6 minutes — need the workflow pushed to GitHub. That needs a push, and `AGENTS.md` says no pushing without asking. Everything else is done and checked.
